    Hugo Stack主题装修记录（三）

    2026-07-29
    3592字
    8 分钟
    --

    本次主要记录最近对 Hugo Stack 模板做的又一轮整理，主要集中在：首页时间轴、Archive 页面响应式、左右侧栏细节、文章阅读体验、搜索页空状态，以及模板配置和样式文件结构。

    最后更新 · 2026-07-29

    01 给首页补一条连续的时间轴

    前面已经把首页文章按年份做了分组，但只有年份标题时，各组内容之间还是稍微有些松散。
    这次在年份标题左侧增加了一条纵向时间轴，并用圆点标记每一个年份，让首页从上到下更像一段连续的写作记录。

    时间轴本身没有增加新的信息，只是把原有的年份分组重新串了起来。
    颜色也没有做得很重，仍然沿用站点的 accent 色，并通过透明度拉开线条、节点和背景之间的层次。

    对应修改文件：

    • assets/scss/custom/_home.scss

    02 修正首页时间轴的对齐

    时间轴完成以后，又对年份圆点和竖线的位置做了一轮微调。
    原本圆点和线条分别使用自己的偏移值，在不同年份标题字号和不同屏幕宽度下，视觉上会有一点没有落在同一条轴线上的感觉。

    这次把左侧缩进和时间轴位置统一成两组变量：

    1
2

    --home-timeline-indent: 24px;
--home-timeline-axis: 8px;

    年份圆点、竖线和文章列表都基于同一套坐标计算，移动端只需要缩小整体缩进，不再分别修正每个元素。
    这样桌面端和手机端的轴线位置会稳定一些，后面继续调整卡片宽度时也不容易再次错位。

    对应修改文件：

    • assets/scss/custom/_home.scss

    03 调整首页卡片的分类色反馈

    首页文章卡片原本使用统一的 accent 色作为 hover 反馈，单独看没有问题，但和卡片上方的分类标签并没有太强的联系。

    这次把每篇文章第一个分类的颜色变量传到卡片容器上。
    鼠标移入卡片时，左侧高亮线和边框会跟随当前文章的分类颜色变化，而不是所有文章都使用同一种颜色。

    整体动画仍然保持得比较轻：

    • 卡片只向上移动一点
    • 左侧增加一条分类色细线
    • 阴影和边框轻微变化

    这样既能让不同分类有一点辨识度，也不会让首页变成颜色过多的数据面板。

    对应修改文件：

    • layouts/partials/article-list/home-grouped.html
    • assets/scss/custom/_home.scss
    • assets/scss/custom/_motion.scss

    04 重新整理首页卡片的信息排布

    首页卡片中的日期、字数、阅读时间和浏览次数这次都继续保留，没有减少信息项。
    主要调整的是桌面端的排列方式：分类、标题和元信息重新回到从上到下的阅读顺序，避免右侧信息区看起来过于独立。

    手机端仍然会隐藏字数统计，给标题和其他信息留出空间；桌面端则完整显示四项内容。
    同时也重新收了一遍卡片内边距、标题字号、图标间距和分页样式，让信息虽然完整，但整体不会显得太挤。

    对应修改文件：

    • assets/scss/custom/_editorial-layout.scss
    • assets/scss/custom/_legacy.scss

    05 调整 Archive 页的年份顺序

    Archive 页面前面已经增加了年度概览和年份导航，但年份顺序还是从较早年份开始。
    对于日常查看来说，最近写的内容通常更常用，所以这次把顶部年份导航和下面的文章分组都改成了从新到旧排列。

    这次只调整展示顺序，没有改变文章统计方式。
    页面上的总文章数、总字数，以及每一年的文章数和字数仍然沿用原来的计算逻辑。

    对应修改文件：

    • layouts/_default/archives.html

    06 重做 Archive 年份导航的响应式布局

    之前的年度导航更接近横向时间轴，每个年份宽度还会根据文章数量变化。
    实际使用以后发现，这种方式在桌面端不够整齐，在手机端也不容易一眼看出后面还有内容。

    这次改成了三种布局：

    • 宽屏下每行显示五个年份
    • 中等宽度下每行显示四个年份
    • 手机端改成横向滑动

    手机端同时增加了右侧渐隐和“横向滑动查看更多年份”的提示，并使用 scroll snap 让每个年份卡片停靠得更自然。
    桌面端则保持等宽网格，年份数量变化时仍然能够对齐。

    对应修改文件：

    • layouts/_default/archives.html
    • assets/scss/custom/_archive.scss

    07 修正 Archive 顶部标签和分类高度

    Archive 顶部的标签和分类使用的是同一套卡片，但标签区之前还保留了主题 widget tagCloud 的类名。
    这组主题样式会额外影响内部间距，所以两个区块虽然结构相同，实际显示时高度并不完全一致。

    这次去掉了标签区多余的 widget 类，让标签和分类都只使用 Archive 自己的布局规则。
    同时在手机端固定为两列，并统一卡片高度、内边距和数量文字的位置。

    对应修改文件：

    • layouts/_default/archives.html
    • assets/scss/custom/_archive.scss

    08 收紧 Archive 页的整体节奏

    除了年份导航和分类卡片，这次也重新检查了 Archive 页面几个区块之间的距离。
    顶部标签、分类、总览文字、年份导航和文章列表原本各自留白都比较充足，叠在一起后会让页面上半部分显得偏长。

    这次主要收紧了区块间距和移动端留白，没有继续增加新的装饰。
    现在顶部信息仍然完整，但从分类区进入年度文章列表会更连贯一些。

    对应修改文件：

    • assets/scss/custom/_archive.scss

    09 整理左侧栏的站点身份区

    左侧栏里的 GitHub 链接原本单独占据一行，在图标数量较少时会显得有些零散。
    这次把社交链接移动到站点名称旁边，并做成一个较小的圆形按钮，让名称、简介和外部链接形成一个更紧凑的身份区。

    同时补上了社交链接的 aria-label，并继续尊重菜单中的 newTab 配置。
    手机端不再用绝对定位放置图标，避免标题长度变化以后产生错位。

    对应修改文件：

    • layouts/partials/sidebar/left.html
    • assets/scss/custom/_sidebar.scss

    10 调整导航对比度和移动端菜单按钮

    左侧导航中未选中的项目原本颜色偏浅，在浅色背景下看起来有些弱。
    这次把普通导航文字调整为一组更稳定的灰蓝色，当前页面仍然通过主题的强调色区分，不额外增加背景块。

    移动端的汉堡按钮也改成了较深的蓝灰色。
    这部分没有改变菜单结构，只是让导航入口在浅色模式下更容易识别一点。

    对应修改文件：

    • assets/scss/custom/_sidebar.scss
    • assets/scss/custom/_tokens.scss

    11 统一右侧组件标题和目录样式

    右侧搜索、归档和文章目录之前都有自己的图标和标题结构，放在一起时稍微有些重复。
    这次隐藏了 widget 自带的大图标，只保留统一的短线标记和文字标题，让右侧栏更像同一组辅助阅读工具。

    文章目录也一起做了调整：

    • 普通目录项降低字重和对比度
    • 当前章节增加左侧强调线
    • hover 位移缩小
    • 内容过长时允许内部滚动

    这样目录仍然能明确提示当前阅读位置，但不会一直抢正文的注意力。

    对应修改文件：

    • assets/scss/custom/_sidebar.scss
    • assets/scss/custom/_motion.scss
    • assets/scss/custom/_legacy.scss

    12 调整文章开头的摘要和更新时间

    这两篇装修记录开头都有一段说明本次改动范围的引用文字。
    之前普通 blockquote 的字重和背景比较明显，用作摘要时会稍微有些重，所以这次单独给文章第一段引用增加了一套更轻的样式。

    同时把“最后更新”改成了一个较小的 pill，放在摘要和正文之间。
    它仍然是正文内容的一部分，不需要额外修改 Hugo 模板，需要时只要在 Markdown 中加入：

    1

    <p class="article-update">最后更新 · 2026-07-29</p>

    对应修改文件：

    • assets/scss/custom/_article.scss
    • content/post/Hugo Stack主题装修记录.md
    • content/post/Hugo Stack主题装修记录（二）.md

    13 补齐搜索页的空状态

    搜索页在没有输入关键词时，结果标题和结果列表都是空的，但仍然会占据一部分页面结构，footer 也会停在页面中间。
    这次增加了一个项目级搜索页模板，并为无结果状态补了单独样式。

    现在空的结果标题和列表会直接隐藏，footer 会自然落到页面底部。
    搜索产生结果以后，原有的列表逻辑仍然照常使用，不影响搜索脚本本身。

    对应修改文件：

    • layouts/page/search.html
    • assets/scss/custom/_search.scss

    14 补充模板中的语义和无障碍信息

    这次在整理页面结构时，也顺手补了一些不太显眼的语义细节。

    主要包括：

    • 搜索框使用 type="search"
    • 搜索表单增加 role="search"
    • 搜索按钮补充 aria-label
    • 搜索结果区增加 aria-live
    • 文章封面优先使用 imageAlt，没有时再回退到标题
    • 只有首页、Archive 和搜索页使用站点名称 h1
    • 社交链接补充可访问名称

    这些调整不会明显改变页面外观，但能让标题层级、键盘操作和辅助技术读取更完整一些。

    对应修改文件：

    • layouts/page/search.html
    • layouts/partials/widget/search.html
    • layouts/partials/article/components/header-entry.html
    • layouts/partials/sidebar/left.html

    15 修正配置中 false 开关失效的问题

    前面关闭相关文章和部分元信息时，发现 Hugo 模板里的 default 对布尔值有一个容易忽略的问题：显式写入的 false 也可能被当成空值，再回退到默认的 true。

    这次把相关文章、阅读时间、头像和社交链接新窗口等开关，都改成先判断配置项是否存在，再读取它的实际布尔值。
    这样在配置中明确写下：

    1

    relatedContent: false

    模板就会真正关闭对应功能，不会再被默认值覆盖。

    对应修改文件：

    • layouts/_default/single.html
    • layouts/partials/article/components/details-entry.html
    • layouts/partials/sidebar/left.html

    16 清理没有继续使用的评论和统计配置

    评论已经切换到 Twikoo，访问统计也已经使用 GoatCounter，所以配置文件里原来保留的 Disqus、Waline、Google Analytics 等空配置已经没有实际作用。

    这次把这些未使用的 provider 配置一起清理掉，只保留当前真正启用的服务。
    这样 hugo.yaml 会更短一些，也能减少以后排查配置时的干扰。

    对应修改文件：

    • hugo.yaml

    17 按页面加载脚本并调整 partial 缓存

    主题的分类配色需要 Vibrant 读取图片颜色，但并不是每个页面都会用到这套逻辑。
    这次把脚本限制在首页、分类页和列表页加载，文章正文等不需要取色的页面不再重复引入。

    同时给 footer 的 partial cache 增加页面 Kind 作为缓存键。
    不同类型页面会使用各自正确的渲染结果，避免因为缓存范围过大而出现页面内容不一致。

    对应修改文件：

    • layouts/partials/footer/components/script.html
    • layouts/partials/footer/include.html

    18 调整 GitHub Actions 的构建和发布流程

    最后也整理了一遍站点的自动构建流程。
    现在 pull request 会执行完整构建检查，但不会触发部署；只有 master 分支推送后才会发布站点。

    Hugo 构建同时打开了路径、翻译和 warning 检查，并在遇到 warning 时直接失败。
    另外补上了并发取消，连续推送时旧任务会自动停止，减少重复构建。

    对应修改文件：

    • .github/workflows/hugo.yml

    19 拆分 custom.scss 的样式结构

    随着首页、Archive、侧栏和文章页的样式越来越多，原来的 custom.scss 已经超过一千行，继续把所有调整写在同一个文件里会越来越难定位。

    这次先保留原有样式作为 _legacy.scss，再把最近这轮调整按职责拆成：

    • _tokens.scss
    • _article.scss
    • _archive.scss
    • _sidebar.scss
    • _home.scss
    • _search.scss
    • _motion.scss
    • _editorial-layout.scss

    入口文件 custom.scss 现在只负责按顺序引入这些模块。
    同时增加了一组很小的设计变量，用来统一表面颜色、边框、弱文字、圆角和阴影。后面继续装修时，可以先复用这组变量，不用每个页面重新写一套近似值。

    对应修改文件：

    • assets/scss/custom.scss
    • assets/scss/custom/_tokens.scss
    • assets/scss/custom/_legacy.scss
    • assets/scss/custom/_article.scss
    • assets/scss/custom/_archive.scss
    • assets/scss/custom/_sidebar.scss
    • assets/scss/custom/_home.scss
    • assets/scss/custom/_search.scss
    • assets/scss/custom/_motion.scss
    • assets/scss/custom/_editorial-layout.scss
