    Hugo Stack主题装修记录（二）

    2026-03-26
    2749字
    6 分钟
    --

    本次主要记录这两天对 Hugo Stack 模板做的一轮整理，主要集中在：首页结构、Archive 页面重做、文章页统一、评论与访问统计，以及 footer 统计修正。

    最后更新 · 2026-03-26

    01 重做 Archive 页面结构

    这次对 Archive 页面做了一轮比较完整的调整，不再只是简单按年份往下列文章，而是在页面顶部补了一层更清晰的结构。

    目前 Archive 页面主要分成三部分：

    • Tags 区块
    • Categories 区块
    • 按年份整理的文章列表

    其中 Tags 和 Categories 都改成了卡片式展示，并且补上了各自的文章计数。
    相比之前默认的列表样式，现在信息会更集中，也更方便快速跳转到某一个分类或标签。

    对应修改文件：

    • layouts/_default/archives.html
    • assets/scss/custom.scss

    02 在 Archive 页面增加年度概览和时间轴

    除了顶部的分类与标签区，这次也在 Archive 页面正文前增加了一组概览信息，用来汇总整个博客的归档情况。

    目前这里会显示：

    • 最早写作年份到最新年份
    • 总文章数
    • 总字数

    在这段概览下面，还增加了一条按年份展示的时间轴。
    每个年份节点都会显示：

    • 当年文章篇数
    • 当年总字数

    点击某个年份后，会平滑滚动到对应年份的归档位置，并短暂高亮该分组。

    对应修改文件：

    • layouts/_default/archives.html
    • assets/scss/custom.scss

    这里算是把原来的 Archive 页，从“简单归档列表”改成了“带概览和快速跳转的归档页”。

    03 调整 Archive 页面文章列表样式

    Archive 页面下面按年份展开的文章列表，这次也一起做了样式整理。

    调整后每条文章会显示：

    • 标题
    • 副标题
    • 日期

    同时整体样式改成了更接近卡片容器下的列表布局，hover 时会有轻微高亮，日期也单独做成了一个较轻的 pill 样式。
    这样整个 Archive 页从顶部分类区、时间轴，到下面文章列表，视觉上会更统一一点。

    对应修改文件：

    • layouts/_default/archives.html
    • assets/scss/custom.scss

    04 搜索页样式同步调整

    除了 Archive 页面，这次也顺手把搜索页的结果列表样式统一整理了一遍。

    原本搜索结果区和 Archive 列表在风格上有些割裂，这次主要把搜索页结果容器、条目 hover 反馈以及列表分隔方式，统一到和 Archive 页接近的视觉逻辑里。
    这样搜索页在使用时，不会再像是另一套独立样式，整体和站点其他列表页面会更协调一些。

    对应修改文件：

    • layouts/partials/widget/search.html
    • assets/scss/custom.scss

    05 TOC 组件样式调整

    这次也一起调整了文章页目录组件的样式，主要是让 TOC 和右侧其他小组件之间的观感更统一一点。

    这部分改动不算大，主要还是集中在边距、层次和整体块状感的协调上，让目录区不会显得过于突兀，同时也尽量保留 Hugo Stack 原本比较简洁的结构。

    对应修改文件：

    • layouts/partials/widget/toc.html
    • assets/scss/custom.scss

    06 首页文章按年份分组显示

    之前首页文章是直接顺着往下排，文章数量多了以后，不同年份的内容混在一起，看起来没有那么直观。
    这次把首页文章列表按年份做了分组，在每一组文章左上角增加了年份标题，效果上更接近 Archive 页，但间距和字号会比 Archive 更紧凑一点，避免首页显得太松散。

    实现上还是基于 Hugo 自带分页，只是在当前分页结果上增加了一层 GroupByDate "2006"。
    对应修改：

    • layouts/index.html
    • assets/scss/custom.scss

    这样首页在文章数量逐渐变多后，按年份浏览会更清楚一些。

    07 首页文章卡片点击区域优化

    原来的首页卡片只有标题可以点击进入文章正文，白色卡片的大部分区域都不能点，交互上有些不自然。
    这次把首页文章卡片的点击区域做了扩大，除了分类标签本身保留独立点击以外，其余白色卡片区域都可以直接进入文章。

    同时标签区域边缘也稍微留了一点空间，避免误触。
    对应修改：

    • assets/scss/custom.scss

    这样首页卡片的交互就会更接近常见博客的阅读习惯。

    08 统一文章页与首页的元信息显示

    这次把文章页和首页卡片右侧那一组信息重新整理了一下，统一为：

    • 发布时间
    • 字数统计
    • 阅读时间
    • 浏览次数

    其中浏览次数单独加了一个 eye 图标，放在阅读时间后面。
    文章页和首页都采用同一套结构，这样看起来会更统一，也方便后面继续调整样式。

    对应修改主要包括：

    • layouts/partials/article/components/header-entry.html
    • layouts/partials/article/components/details-entry.html
    • themes/hugo-theme-stack/assets/icons/eye.svg

    另外首页这块也反复微调了间距、字号和图标排列，尽量让日期、字数、阅读时间、访问次数在视觉上保持同一节奏。

    09 合并首页和文章页重复 partial

    前面在调整首页和文章页信息结构的时候，发现标题区和元信息区有不少重复模板。
    如果首页一套、文章页一套分别改，后面很容易出现“文章页改了，首页忘了同步”的情况，所以这次顺手做了一次整理。

    原本拆开的：

    • header-home.html
    • header-single.html
    • details-home.html
    • details-single.html

    现在合并成了统一模板：

    • header-entry.html
    • details-entry.html

    再通过 Mode 参数区分首页和文章页的差异。
    这样以后如果还要继续改标题区、访问次数、字数、阅读时间，维护起来会更稳一些。

    10 统一文章页页头分类和页尾标签颜色

    之前文章页页头的分类标签，和正文末尾的 tags 颜色并不是同一套逻辑。
    页头颜色是单独算的，页尾 tags 还是走主题默认 accent 色，所以同一篇文章前后看起来会有一点割裂。

    这次把页尾 tags 也改成复用页头那套颜色变量，让页头和页尾保持一致。
    对应修改：

    • themes/hugo-theme-stack/layouts/partials/article/components/tags.html
    • layouts/partials/helper/category-style.html
    • assets/scss/custom.scss

    这样一来，同一篇文章前后的标签风格就统一了。

    11 交互效果优化

    这两天也顺手整理了一些页面交互细节，主要是把 hover 状态下的视觉反馈做得更自然一点。

    前面一度尝试过更明显的背景块和位移动画，但实际效果有点突兀，而且容易影响原本的版面节奏，所以最后收成了一版更克制的写法：

    • hover 时文字和图标轻微加深
    • 局部区域增加较轻的高亮反馈
    • 尽量不改变原本的尺寸和布局

    这部分主要体现在侧边栏菜单、Archive 列表以及部分卡片交互上。
    整体目标不是把动画做得很重，而是让页面在鼠标移入时有一点明确反馈，但又不破坏 Hugo Stack 原本比较干净的风格。

    对应修改：

    • assets/scss/custom.scss

    12 关闭相关文章显示

    原本文章页底部会显示相关文章，但这次整体更想保留一个相对简洁的阅读流，所以先把相关文章这一块关掉了。

    修改方式是：

    1. 在配置里增加开关
    2. 在文章页模板中按开关决定是否渲染

    对应文件：

    • hugo.yaml
    • themes/hugo-theme-stack/layouts/_default/single.html

    这样以后如果还想重新启用，也只需要改一行配置即可。

    13 评论系统切换为 Twikoo

    原来评论系统使用的是 Waline，但这次因为后端配置和维护上的问题，最后切换成了 Twikoo。
    主题本身已经支持 Twikoo，所以这里只需要打开评论、切换 provider，并填入后端地址即可。

    对应修改：

    • hugo.yaml

    About 页面则单独保留不启用评论，在 front matter 里设置：

    1

    comments: false

    对应文件：

    • content/page/about/index.md

    这样最终的效果就是：普通文章页可以显示评论区，About 页面保持关闭。

    14 访问统计从 Twikoo 改为 GoatCounter

    一开始也尝试过直接使用 Twikoo 的访问统计，但在首页和文章页统一展示时并不算稳定，所以最后把访问统计单独拆出来，改用 GoatCounter。

    这样评论和访问统计就各做各的：

    • 评论交给 Twikoo
    • 访问统计交给 GoatCounter

    对应修改主要有：

    • layouts/partials/head/custom.html
    • assets/ts/custom.ts
    • layouts/partials/article/components/details-entry.html
    • layouts/partials/footer/footer.html

    文章页、首页卡片以及 footer 的总访客数字，都改成从 GoatCounter 取值。

    15 为 GoatCounter 增加失败降级

    GoatCounter 这套访客计数，前提是后台要开启 visitor counter 的公开接口。
    如果接口没开放，页面就拿不到数字。

    为了避免页面直接显示 0 或者 XX 这种不太自然的占位状态，这里顺手补了一个失败降级逻辑：

    • 首页和文章页访问次数取不到时，直接隐藏这一项
    • footer 总访客取不到时，显示 --

    对应修改：

    • assets/ts/custom.ts

    这样即使统计接口暂时不可用，页面也不会显得像坏掉了一样。

    16 修正 footer 的统计口径

    原来 footer 里的文章数和字数统计，直接遍历了站点里所有 Kind = "page" 的页面，这样 About、Archives 之类页面也会被算进去，口径并不一致。

    这次把 footer 的统计方式改成了只统计主内容分区中的正文文章，并且排除 hidden 内容。
    这样 footer 里显示的：

    • 文章篇数
    • 总字数

    就会和首页实际展示的文章口径保持一致。

    对应修改：

    • layouts/partials/footer/footer.html
