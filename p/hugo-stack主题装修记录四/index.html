    上一篇给首页加了一条按年份排列的时间轴。这次升级到 Stack 4，又顺着「怎么找回一篇旧文」改了几处。记得大致月份，可以翻时间轴。只记得某一段写了什么，也可以从搜索结果直接跳过去。文章底下的评论和阅读量，这次也一起整理了。

    01 升级到 Stack 4

    这次把博客用的 Hugo Extended 升到了 0.169.0，Stack 主题升到了 4.0.3。前面几篇里贴过的模板路径，有几处也跟着换了位置。比如要接着改首页，现在要找 layouts/home.html。标题下面的日期和阅读时间，则要去 layouts/_partials/ 下面找。

    头像和之前用来标记字数、阅读量的两个小图标，这次都搬到了站点自己的 assets/ 目录。以后再换主题版本，这几个文件也就不用重新拷一遍了。

    对应修改文件

    • .hugo-version
    • themes/UPSTREAM.md
    • layouts/home.html

    02 把月日放到时间轴左边

    上一篇把年份串了起来，每篇文章的日期还在卡片里面。同一个月连着写几篇，卡片里就要连着读几遍相同的年和月。这次给桌面端单独留了一列日期，首页和 Archive 页共用。

    现在年份放在每组开头，几号就写在文章旁边，和时间轴上的圆点对齐。月份只在这个月的第一篇上方出现一次。手机上横向空间有限，日期还是完整地放回卡片里，把左边的位置留给标题。

    对应修改文件

    • layouts/_partials/article-list/home-grouped.html
    • assets/scss/custom/_timeline-dates.scss

    03 在 Archive 页直接筛选标签

    第一篇装修记录先给标签加了文章数，第二篇又把 Tags 和 Categories 分成两块。写到现在，平时最常用的其实是点一下「技术工具」，看看这个标签下以前写过什么。这次把文章分组统一收进了 tags，Archive 顶部也只留一排带篇数的标签。

    点「技术工具」以后，下方的文章就在原地筛选。展开「年度统计」，每年的篇数和字数也会跟着重算。如果某个月原本排第一的文章被筛掉了，月份会移到下一篇符合条件的文章旁边，左侧日期仍然能连着读下来。

    选中的标签也会写进地址栏。比如把 /archives/?tag=技术工具 发给别人，对方打开就是这组文章。想换回完整列表，点最前面的「全部」就行。

    对应修改文件

    • hugo.yaml
    • layouts/archives.html
    • assets/ts/archiveFilter.ts

    04 从搜索结果跳到正文里的那一节

    比如想找以前改中文字数统计的办法，还记得有个配置叫 hasCJKLanguage，却想不起来写在哪一篇。以前即使搜到了第一篇装修记录，点进去还是得从头翻到「03 字数统计」。

    这次给搜索索引补上了小节标题和锚点。搜这个配置名时，结果里能看到它附近的原文。点文章标题照常从头读，点摘要上方的「跳到章节」就能直接落到「03 字数统计」。要是记得文章全名，完整标题匹配的结果会排在最前面。

    顺手也把搜索框放到了 404 页。碰到失效的文章地址，页面会从网址末尾取一段文字先搜一次，还能接着改关键词。

    对应修改文件

    • layouts/_partials/search/body.html
    • assets/ts/search.tsx
    • layouts/404.html

    05 给手机上的长文补一个随手能打开的目录

    前几篇装修记录一篇能写十几节。电脑上读到中间，右侧就有目录。手机上读到第十节又想翻回第二节，先一路划回篇首找目录，就有点费劲了。

    现在往下读过一段，屏幕右下角会出现「目录」和「回顶」。点开目录会从底部弹出面板，刚刚读到的那一节会高亮，长目录也会滚到对应位置。选好另一节，面板随即收起，正文停在选中的标题。篇首也留了目录入口，刚打开文章就能选一节读。

    正文里的章节标题换成了宋体一类的衬线字，一、二级标题后面接一条渐淡的细线。像这篇这样反复出现文件名和代码的文章，滑过去的时候，也比较容易看出下一节从哪里开始。

    对应修改文件

    • layouts/_partials/article/components/mobile-toc.html
    • assets/ts/readingTools.ts
    • assets/ts/scrollspy.ts
    • assets/scss/custom/_article.scss

    06 把几篇装修记录串成一个系列

    之前读完一篇装修记录，想看下一篇，还得回首页找一个几乎一样的标题。这次给装修记录和每年的 Bangumi 杂记都补了系列顺序。这一篇的顺序就写在文章开头的这两行里。

    1
2

    series: Hugo Stack主题装修记录
seriesOrder: 4

    文章发表以后，Hugo 会按这个顺序在文末放好「上一篇」和「下一篇」。想从第一篇看起，可以展开完整的系列目录。首页和归档里也给几篇装修记录各写了一句副标题，翻列表时就能分清哪篇讲页脚统计，哪篇讲首页时间轴。

    对应修改文件

    • layouts/_partials/article/components/series.html
    • layouts/_partials/article/components/details-entry.html

    07 把 GoatCounter 的阅读量写进页面

    第二篇接入 GoatCounter 以后，首页每张卡片上的小眼睛都得等浏览器去取数。现在打开一页文章列表，标题和阅读量会一起出来。浏览器仍然负责上报这次访问，页面上显示的数字由 GitHub Actions 每六小时从 GoatCounter 同步一次，再由 Hugo 写进 HTML。

    这里特意区分了 0 和 —。刚发的文章，查过确实还没人看，就显示 0。碰上接口超时，先沿用上次拿到的数字。连上次的记录也没有，才显示 —。

    对应修改文件

    • scripts/sync-view-counts.py
    • layouts/_partials/article/components/details-entry.html
    • .github/workflows/hugo.yml

    08 把评论搬到 GitHub Discussions

    之前文章下面用的是 Twikoo。这次改成每篇开放评论的公开文章对应一个 GitHub Discussion。看留言还是在博客里往下翻，已有的评论和回复都随正文一起显示。要回一句，点「参与讨论」就会打开这篇文章对应的 GitHub 讨论。

    旧留言也单独留了一份。比如《Bangumi 2024年杂记》下面那条「测试」，换完评论系统以后照样能看到。GitHub 上后来新增或修改的留言，由工作流每小时同步一次，再显示到博客里。

    对应修改文件

    • layouts/_partials/comments/provider/discussions.html
    • scripts/sync-discussions.py
    • data/legacy_comments.json

    09 在页脚留一个 RSS 订阅入口

    最后顺手收了一下 RSS 入口。页面上只在最下面的运行时间旁边留了一个「RSS 订阅」，读到文章末尾就可以直接点。习惯用阅读器的，也可以把任意一篇公开文章的网址贴进去，支持自动发现的阅读器就能找到全站的全文订阅。

    这次还修了《Bangumi 2024年杂记》的链接。这篇文章曾经用过 bgm 和 bangumi 两种写法，现在把 bangumi 固定为正式地址，另一种放进别名里。以后翻到原来存的书签，两条路都能回到同一篇文章。

    对应修改文件

    • layouts/_partials/head/head.html
    • layouts/_partials/footer/footer.html
    • content/post/bgm-2024年杂记.md
